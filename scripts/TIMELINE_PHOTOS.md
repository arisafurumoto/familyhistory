# 年表写真の最適化

年表写真のみを幅680px以下・WebP品質80に変換する。縦横比、透過、対応するアニメーションを維持し、小さい画像を拡大しない。表示レイアウトと人物写真は変更しない。

アップロードはCloudflare Images bindingで一度変換してR2に保存する。編集時はDB更新後に旧画像の参照を確認して削除する。失敗時は元の参照を維持する。削除に失敗したオブジェクトはログにキーが残るため保守時に再確認する。

## 本番移行

Cloudflareの対象アカウントでWranglerへログイン済みであること。先に新しいアップロード処理をテスト・公開する。以下のフォルダーは同じ移行の全段階で共用する。`work/`はGit管理外。元画像を含むため共有しない。

```sh
npm run photos:optimize -- prepare work/timeline-photo-backup --remote
npm run photos:optimize -- apply work/timeline-photo-backup --remote
```

`prepare`は本番を変更せず、現在の年表画像参照、元画像、変換画像、寸法、容量、チェックサムを保存する。失敗画像は理由付きで記録する。`apply`は変換画像をアップロードして再ダウンロードし、チェックサムを照合してから、元キーがまだ一致するイベントだけを更新する。原寸画像はこの段階では削除しない。再実行は同じ変換結果を使用し、再圧縮しない。

ログインしたサイトでPC・スマートフォン表示、写真の向き・透過・アニメーションを確認する。未ログインで画像が401になることも確認する。確認後のみ旧画像を削除する。

```sh
npm run photos:optimize -- cleanup work/timeline-photo-backup --remote --verified
npm run photos:optimize -- report work/timeline-photo-backup --remote
```

`cleanup`は元画像のローカルバックアップと新画像のチェックサムを照合し、年表・人物から旧キーへの参照がない場合だけ削除する。参照競合で使われなかった新画像は削除する。既存の未参照画像の一括整理は行わない。`report`の容量は変換候補の比較値であり、実際に削減済みなのは`complete`の画像のみ。

## 復旧

`manifest.json`の`rows`が元の画像参照・名前・形式、`entries`が旧キーとバックアップの対応表。旧画像を削除済みの場合は、チェックサム一致を確認した`.original`を旧キーへ元のContent-TypeでR2に戻す。その後、**現在もこの移行の新キーを参照する行だけ**元のキー・名前・形式へ戻す。作業後に利用者が変更した写真を上書きしない。復旧と表示確認が終わるまで最適化画像を削除しない。

バックアップは自動削除しない。元画像とマニフェストを残すことで、R2から原寸画像を削除した後も復旧できる。
